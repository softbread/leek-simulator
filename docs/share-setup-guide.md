# 单只 A 股：数据准备与运行指南

目标是先记录一个时间点的市场情绪，再观察它在代理人交易、同伴影响和价格反馈下如何演化。
系统现在会分别保存“起点观测”和“未来模拟”，结果页也会分开展示。

## 1. 安装并启动

在项目根目录执行：

```bash
npm run setup
cd backend
uv sync
uv run playwright install chromium
cd ..
npm run dev
```

打开 `http://localhost:3000`。LLM 配置是可选的；未配置仍可运行仿真。
LLM 当前用于分析报告与问答，不代表每个交易者都是 LLM。

## 2. 每只股票需要准备什么

| 信息 | 是否必需 | 如何填写 / 当前如何使用 |
| --- | --- | --- |
| 股票代码 | 必需 | 如 `SH600519` 或 `600519`；确认代码与名称一致 |
| 股票名称 | 必需 | 官方简称；也是资讯与讨论搜索关键词 |
| 行业/板块 | 必需 | 填一个具体且相关的板块，如“白酒”；用于板块资讯与讨论搜索 |
| 大盘检索词 `market_keyword` | 可选 | 默认“A股”；与股票名、板块分开检索，用于独立的大盘新闻与讨论 |
| 初始价格 | 必需 | 元/股，与快照对应的最近成交价或收盘价；系统不自动拉取实时股价 |
| 流通盘规模 | 必需 | `small/mid/large/mega`，当前是价格冲击模型的合成流动性档位，并非真实流通股本 |
| 市场环境 | 必需 | `neutral/bullish/bearish/volatile`；这是你设定的情景假设，不是系统测出的情绪 |
| 推演长度 | 必需 | 1-5 个交易日，每日 48 个五分钟 tick |
| 代理人数 | 必需 | 500-2000，默认 1000 |
| 快照时间 | 可选 | ISO 时间，如 `2026-10-19T15:00:00+08:00`；留空表示构建世界时刻 |
| 近期行情 | 可选 | 同一频率、同一复权口径的时间/收盘价/成交量；影响起点动量和流动性 |
| 大盘宽度 `market_breadth` | 可选 | 同一股票池的涨跌家数、涨跌停数及晋级率，用于独立的大盘周期候选判断 |
| 雪球讨论 | 可选但关系到情绪观测 | 在第二步登录后抓取个股与板块讨论；缺失时只能使用新闻代理 |
| 新闻 | 自动获取 | 东方财富按股票名和板块检索；仍需复核是否同名、过期或无关 |
| 研究、公告、纪要 | 可选 | 上传 PDF/TXT/Markdown；作为带方向的材料输入，使用关键词规则解析 |
| 人群比例 | 可选 | 调整五类策略的权重；默认比例是假设，尚未用真实投资者统计校准 |
| 随机种子 `seed` | API / 配置文件可选 | 固定整数，便于同一批输入的重复实验 |

“补充说明”目前作为场景元信息保存；要让材料进入世界模型，请上传文件或通过适配器提供结构化种子。
当前不接入券商账户，不需要资金密码，也不会下真实订单。

## 3. 填写近期行情

首页的“近期行情”框接受 JSON 数组。下面只是格式示例，不是真实行情：

```json
[
  {"timestamp":"2026-10-19T14:45:00+08:00","close":99.20,"volume":100000},
  {"timestamp":"2026-10-19T14:50:00+08:00","close":99.70,"volume":130000},
  {"timestamp":"2026-10-19T14:55:00+08:00","close":100.00,"volume":160000}
]
```

数据要求：

- 从旧到新严格递增，不要混入快照之后的数据。
- `close` 为正数，单位元；`volume` 为非负数，单位股。数据源若以“手”为单位，需要先转换。
- 每条记录使用相同间隔；不要把日线成交量和五分钟成交量混在一起。
- 至少两条才能计算动量，最多 500 条。只有一条时会提示数据不足。
- 初始价格应与最后一条行情对应。相差超过 2% 时页面会提示检查口径。
- 当前价格动量是末价/首价减一；量比是末条成交量/此前各条平均成交量。

行情可从你使用的行情软件或已有数据源导出后转换。当前 UI 没有自动行情下载功能，
也不会自动识别股票是否 ST、除权、停牌，需在输入前自行统一数据口径。

## 4. 采集“当前情绪”

1. 创建场景，进入“市场环境与人群初始化”。
2. 点击“打开雪球登录”，在弹出的浏览器中登录。
3. 回到应用，点击“我已完成登录”。
4. 点击“构建 world_state”，采集资讯与讨论并形成起点快照。
5. 查看“起点市场情绪”的时间、来源、样本量、价格变化和提示。
6. 确认后点击“生成市场上下文”，再进入价格仿真。

起点快照包括：综合情绪、个股讨论、板块讨论、新闻情绪、讨论样本数、热度、
近期价格变化、量比，以及数据缺失/过期提示。分数范围 -1 到 1。
“偏多/偏空/中性”是关键词启发式标签，并非经过校准的概率。

来源标识：

| 标识 | 含义 |
| --- | --- |
| `observed` | 接入了时间有效的讨论窗口；不表示覆盖了全部市场或独立验证了数据真实性 |
| `news_proxy` | 没有有效讨论，只能以新闻构造代理情绪；不能当作真实雪球情绪 |
| `insufficient` | 缺少有效讨论与新闻；仍可做假设实验，但没有当前情绪观测基础 |

新闻会排除快照之后、影响期到期或时间无效的输入；默认影响期为发布时间起 72 小时。
讨论窗口排除超过 7 天、晚于快照或时间无效的输入，较旧讨论降低权重。
当前雪球页面片段使用抓取时间作为窗口，尚未逐条验证原帖发布时间，因此页面会提示复核时效。
热度主要是样本量的对数代理，不是全站真实流量。

过去时间的研究需要当时已保存的新闻和讨论。实时抓取不能重建过去的市场；
若填写过去快照时间，今天抓到的讨论会被排除。

## 5. 先观测，再看模拟发展

起点情绪进入代理人的初始信念，也影响世界的散户情绪、板块压力和动量。
原始情绪种子随后随模拟时间衰减，同伴信念、交易与价格反馈继续改变市场。
系统不会把今天抓到的多个讨论窗口当成明天已知的情绪路径。

### 大盘、个股与板块分开

| 层级 | 默认输入来源 | 传导 |
| --- | --- | --- |
| 大盘 `market` | 大盘检索词的宏观/全市场新闻与讨论；可由适配器接入独立宏观数据源 | 影响整体风险偏好、宏观交易者与政策压力 |
| 个股 `ticker` | 股票专属新闻、公告与雪球个股讨论 | 影响该股交易者的信念、追涨/卖出与同伴传播 |
| 板块 `sector` | 行业新闻与行业讨论 | 提供板块传导，不代替大盘或个股 |

三个层级分别保存分数、样本数、来源和缺失状态。大盘利好与个股利空可以同时存在。
某层级缺失时会明确标记，不会借其他层级数据冒充。综合分数只是辅助概览，默认权重为
个股 60%、大盘 25%、板块 15%，仅在有数据的层级间归一化。
默认抓取使用相同网站的独立检索流；通过适配器可接入不同网站或自有数据源，
用新闻的 `affected_scope` 或讨论的 `metadata.scope` 标记 `market/ticker/sector`。

### 新闻的三天影响期

默认采用 **72 个自然小时**，从原始发布时间算起，线性衰减：
发布时间权重为 1，36 小时为 0.5，72 小时起为 0。反复抓取或重跑不会重置发布时间。
模型在后续每轮重新计算新闻影响，包括它派生的世界状态和策略偏向。
这是一项默认建模假设，不是声称所有新闻都有相同寿命。较持久事件可通过
`NewsItem.metadata.sentiment_lifetime_hours` 显式设置其他正数小时（最多 720）。
未带发布日期的上传材料默认以快照时间作为观测起点，使用相同三天衰减；
需要精确时效的公告应作为带 `published_at` 的规范化新闻接入。

### 可选：输入大盘复盘数据

首页“大盘宽度数据”框接受如下格式（仅格式示例，不是真实市场数据）：

```json
[
  {"timestamp":"2026-10-16T15:00:00+08:00","advancers":1800,"decliners":3000,"limit_up":25,"limit_down":50,"promotion_rate":0.25,"source":"你的复盘数据源"},
  {"timestamp":"2026-10-19T15:00:00+08:00","advancers":3000,"decliners":1800,"limit_up":70,"limit_down":10,"promotion_rate":0.55,"source":"你的复盘数据源"}
]
```

`promotion_rate` 是同口径涨停晋级比例，取 0-1；未提供时不贡献方向。所有计数为非负整数。
时间必须递增且不晚于快照；最多 250 条。缺少这些数据时，大盘周期显示“证据不足”。
系统不会自动抓取这些全市场统计，也不会用模拟的单只股票成交推断全市场涨跌停家数。

结果新增可用买入资金比例、亏钱效应与个股周期阶段。模拟资金接近用尽时，
即使文字情绪仍偏多，追涨行为也会减弱；盈亏体验和隔夜情绪可以改变下一阶段的参与。
这些是未校准的状态描述，不能把“底部震荡”理解为必然反转。
参考文章与具体模型边界见 [情绪周期模型说明](sentiment-cycle-model.md)。

新闻先影响情绪与交易决策，再由交易净需求推动价格，不直接给股价加减一个“新闻涨幅”。
三天后关闭的是新闻的外部推动；已形成的持仓、记忆、盈亏与群体反馈可以继续产生后果。
固定的 `market_regime` 是用户假设，独立于新闻，不随某条新闻自动消失。

模拟时间包含午休、隔夜与周末的真实时间跨度；只在五分钟交易槽推进交易。
目前跳过周末，但没有完整的交易所节假日日历，因此节假日前后的时间映射仍是近似。

结果页应分开阅读：

- 起点快照与输入历史行情：你提供或采集的观测基础。
- 后续价格、成交、情绪与群体信念曲线：模型生成的假设路径。
- 交易者记忆：检查某个代理人何时改变信念以及如何交易。
- 分析师：可问“当前情绪快照是什么”“谁贡献了最多净买入”等。

想比较情景时，保留同一份 `prepared_context.json` 和 `seed`，通过独立环境运行对照；
改变市场假设或人群比例后重新构建世界。重新抓取会改变数据，不能视为只改了一个变量。
重建同一个 run 会清除该 run 的下游结果，重要对照应使用不同 run。

## 6. API / MiroFish 接入

创建 run 时可增加：

```json
{
  "market_snapshot": {
    "as_of": "2026-10-19T15:00:00+08:00",
    "recent_prices": [
      {"timestamp":"2026-10-19T14:50:00+08:00","close":99.70,"volume":130000},
      {"timestamp":"2026-10-19T14:55:00+08:00","close":100.00,"volume":160000}
    ]
  }
}
```

这是附加字段示例；仍需提供表格中的必填场景字段。MiroFish 配置将其放在
`market_scenario.market_snapshot`，并在 `seed_inputs` 中提供规范化新闻和讨论。
完整配置形状见 `backend/examples/market_mirofish.json` 与 [接入架构](market-architecture.md)。

每次构建保存 `sentiment_snapshot.json` 和 `world_state.json`；运行后另有
`prepared_context.json`、`world_timeline.json`、`agent_states.json`、`results.json`。
它们位于 `backend/uploads/market_runs/<run_id>/`，可用于追溯输入和解释结果。

## 当前模型边界

当前仍是简化价格冲击模型：固定每日 10% 价格边界，未完整实现不同板块规则、T+1、
整手约束、真实订单簿和交易费用。策略、人群与情绪权重尚未进行预测准确率校准。
单条价格路径用于检查情景发展，不代表已验证的目标价或上涨概率。
